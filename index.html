Review the recipient and amount, then exchange nearby. Use QR, Bluetooth, or Wi-Fi Direct. Experimental NFC uses a two-tap flow on supported phones.

Your offline receipt stays pending until sync. When you reconnect, the server settles the first valid redemption—once, not again on every retry.

Does Paila move real money?

Not in the current release. Paila uses test credit only—not real NPR, a bank balance, or redeemable funds. There is no cash-out, and the server refuses real-money mode.

The website preview is an illustration. It does not connect to a wallet, create a real transaction, or move any funds.

Is an offline receipt already settled?

No. An offline exchange and settlement are different steps. The signed exchange is stored locally. Settlement happens after reconnecting, when the server accepts the first valid redemption.

Offline double-spending is not fully solved: a compromised phone could sign the same note twice. Only the first valid redemption settles. Don’t treat a pending receipt as a guaranteed payment.

Which nearby methods can I use?

Paila supports QR exchange, Bluetooth, and Wi-Fi Direct on compatible Android devices. Hardware, operating system support, and permissions can affect availability.

NFC is experimental. It uses a two-tap exchange between supported HCE-capable phones, rather than promising universal tap-to-pay.

What protects the wallet—and can I recover it?

Signing keys use ECDSA P-256 in the Android Keystore, and local storage is encrypted with AES-GCM. Issuer keys stay on the server.

There is currently no account recovery. Uninstalling loses the test wallet. APK obfuscation is not an impenetrable security boundary, and this build must never be used with real funds.
